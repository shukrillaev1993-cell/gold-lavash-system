# GOLD LAVASH — мобильные приложения (Android / iOS)

Это не отдельная система — это тонкая нативная обёртка (WebView / WKWebView)
вокруг уже существующей и синхронной веб-системы GOLD LAVASH
(`?mobile=1` — уже готовый мобильный интерфейс, см. `MobileUI.js` в основном
проекте). Никакой отдельной базы данных нет: обёртка просто открывает тот же
рабочий адрес и даёт нативный доступ к камере телефона для полей вида
`<input type="file" capture="environment">` (фото ОС, инвентаризация и т.п.) —
обычный встроенный браузер это не всегда умеет надёжно, отдельное приложение
даёт полный контроль над этим.

Все данные читаются/пишутся напрямую в те же Google Sheets, что и веб-версия —
синхронизация автоматическая, второй базы не появляется.

- [ANDROID_SETUP.md](ANDROID_SETUP.md) — сборка и публикация Android-приложения
- [IOS_SETUP.md](IOS_SETUP.md) — установка на iPhone без своего Mac (через
  облачную сборку Codemagic + Sideloadly/AltStore) и публикация в App Store

Локальный git-репозиторий в корне проекта уже создан (первый коммит сделан).
Для iOS-сборки в облаке его нужно один раз отправить на GitHub — см.
[IOS_SETUP.md](IOS_SETUP.md), шаг 1. Файл `codemagic.yaml` в корне проекта
уже настроен под это.

## Важное ограничение этой сессии

Я (ассистент) работаю в окружении Windows без Android SDK и без Mac/Xcode —
поэтому:
- Android-проект (`android/`) — это полный исходный код проекта Gradle,
  готовый к открытию в Android Studio, но я не могу сам его собрать/запустить
  здесь и проверить на устройстве.
- iOS — на Windows Xcode-проект в принципе невозможно собрать или открыть.
  Я собрал полный проект (`ios/GoldLavash.xcodeproj`) вручную, текстом, без
  возможности открыть его в Xcode и проверить — структуру и все ссылки между
  файлами проверил насколько это возможно (баланс скобок, совпадение всех
  идентификаторов объектов, валидность XML/plist), но первую реальную сборку
  увидим только в облаке через Codemagic. Если будет ошибка сборки — пришлите
  лог, поправлю.

Если при сборке или тестировании что-то не заработает — пришлите текст ошибки,
я поправлю исходный код.

## Если понадобится изменить адрес системы

Обе обёртки указывают на **рабочий деплой** по фиксированному deployment id
(`AKfycbyfKu_QKGUOu00GeXmNwie5VTPTgXO6M2wKORUrVfwMR2zvkePfi9nqiVC34BoFAj_G`).
Пока обновления публикуются командой `clasp deploy -i <тот же id>`, адрес не
меняется и в приложениях ничего трогать не нужно. Менять адрес нужно только
если когда-нибудь будет создан совершенно новый деплой с другим id — тогда
поменять строку:
- Android: `app/src/main/res/values/strings.xml` → `app_url`
- iOS: `ViewController.swift` → `appURLString`
